# Gill Offline

个人项目橱窗站。主页用「格子」拼成一扇橱窗来陈列项目，管理页带密码，可以增删改格子和拖拽排序。

- 主页 `/`：左上角是 `title.png`，下面是格子组成的橱窗；`logo.svg` 用作站点图标和页脚标记。
  两张图都在 `assets/` 里，页面上按 `/assets/` 访问。
  主页是纯展示的，页面上**没有任何管理入口**，只能靠直接输网址进管理页。
- 管理页 `/admin`：密码来自部署时的环境变量 `ADMIN_PASSWORD`，登录后可编辑一切。
- 用户页 `/user`：注册 / 登录，注册需要邀请码，进去是属于自己的小站（见「多用户」）。
- 部署：一个容器里跑 nginx（TLS + 反向代理）+ Node 应用，证书从宿主机 `/app/ssl` 挂载进容器同一个路径。

```
.
├── assets/                  # 站点自带的图片（logo.svg / title.png），首启时播种到数据目录
├── build_run.sh             # 构建镜像 + 启动容器，一条命令搞定
├── web/                     # 前端静态页面（无构建步骤）
│   ├── index.html           # 主页橱窗
│   ├── admin.html           # 管理页
│   ├── css/  js/
├── server/                  # 零依赖 Node 后端（无 npm 依赖包）
│   ├── index.js             # 静态文件 + 路由
│   ├── api.js               # JSON 接口
│   ├── auth.js              # 密码校验、会话 cookie、登录限流
│   └── store.js             # site.json 读写与字段校验
├── data/site.json           # 示例内容（只读，用来播种运行时数据目录）
├── data.local/              # node 直跑时的运行时数据（自动生成，不进 git）
└── docker/                  # Dockerfile、nginx 配置模板、entrypoint
```

运行时数据和代码是分开的：容器部署的数据全部放在宿主机的 `/app/data`（挂进容器还是这个路径），
仓库里的 `assets/` 只是首次启动时的播种，之后站点服务的是 `/app/data/assets/` 里的那份。
拉代码、重建镜像、甚至删掉整个仓库都不会动到内容。见下面「数据」一节。

## 格子

每个格子有 **尺寸**、**类型**、**边框**、**悬浮详情** 四组配置。

| 尺寸 | 图形 | 占用 |
| --- | --- | --- |
| 方形 `1x1` | ▪ | 宽 1 × 高 1 |
| 矩形 `1x2` | ▪▪ | 宽 2 × 高 1 |
| 长矩形 `1x4` | ▪▪▪▪ | 宽 4 × 高 1 |
| 大方形 `2x2` | 2×2 方块 | 宽 2 × 高 2 |
| 大方块 `3x3` | 3×3 方块 | 宽 3 × 高 3 |
| 巨方块 `4x4` | 4×4 方块 | 宽 4 × 高 4 |
| 大矩形 `2x4` | 4×2 方块 | 宽 4 × 高 2 |
| 宽横幅 `3x6` | 6×3 方块 | 宽 6 × 高 3 |
| 全宽横幅 `4x8` | 8×4 方块 | 宽 8 × 高 4 |

宽格子会跟着窗口收窄——只减列数、不减行数，所以它会越来越接近方形，但不会撑破一行：
8 列的 `4x8` 在 1380px 以下变 6 列、1040px 以下变 4 列，6 列的 `3x6` 同理，
手机上（≤700px）宽格子统一收到 2–3 列。

### 每行列数

管理页棋盘上方那行工具条里有个 **列数** 设置（就在「共 x 个格子」右边），决定橱窗一行摆几个格子：

| 取值 | 行为 |
| --- | --- |
| 自动（默认） | 窗口多宽就铺几列，单个格子最大 152px（页面内容区最宽 1600px，所以最多 9 列） |
| 3–12 列 | 格子**等分整行宽度**：选 3 列，格子就很大；选 12 列，格子就很小很密 |

固定列数时宽格子会按当前列数封顶（`4x8` 在 6 列布局里就占满 6 列），窄窗口也会自动减少列数而不是把格子挤成碎块（每格不少于 96px）。
所以「4 列 + 一个 `4x4`」这类排布在手机上依然能看。

### 格子间隔

同一个工具条里的 **间隔** 有三档，文件里存成 `site.gap` 的 `s` / `m` / `l`：

| 取值 | 间隔 | 适合 |
| --- | --- | --- |
| 紧凑 `s` | 8px | 格子多、想要一整面墙的感觉 |
| 标准 `m`（默认） | 16px | 现在的样子 |
| 宽松 `l` | 28px | 格子少、想让每块更独立 |

它同时决定主页、管理页的棋盘和抽屉里的预览，所以改完立刻能看出效果。固定列数时格子会随间隔自动变小一点，
整行宽度不变。

### 棋盘缩放

工具条末尾的 **缩放** 有五档：15% / 25% / 50% / 75% / 100%，**只影响管理页的棋盘视图**，
不改动任何数据，也不影响主页。格子排得密时缩小一档，一眼看全整块棋盘。

缩小后棋盘**居中显示**，两侧留空——网格只画棋盘自己那一块，不会铺满整个面板，所以一眼能看出
画布到哪儿为止。格子与间隔是同比例缩小的（50% 正好是一半），拖动和吸附按缩放后的刻度算，
缩到 15% 也照样准。缩放是「这次打开管理页」的偏好，不写进 `site.json`，刷新后回到 100%。

### 棋盘布局（自由摆放）

管理页的格子区域就是一块棋盘：**左边最多 12 列**，格子按坐标摆，不再由浏览器决定位置。

| 操作 | 做法 |
| --- | --- |
| 新建 | 在空白处按住拖出想要的大小，松手就落子（单击 = 1×1） |
| 新建（挑尺寸） | 棋盘上方的 **＋ 添加格子**：先落一颗 1×1 在**最下面**，抽屉里点「尺寸」模版（1×1、2×2、3×6…）改成想要的大小 |
| 移动 | 按住格子拖到别处（**触屏上要按住约 1 秒**，见下） |
| 改尺寸 | 拖格子右下角的小方块；也可以在抽屉里直接填「宽 / 高」 |
| 精确定位 | 直接拖（缩放 100% 时最容易对准格子）；抽屉里没有数字框 |
| 编辑内容 | 单击格子打开抽屉；悬停时右上角有编辑 / 复制 / 删除 |

「尺寸」模版只在**＋ 添加格子**打开的那一次出现 —— 那是唯一「尺寸还没定」的入口，
先落一颗 1×1，再点模版改成想要的大小。其余入口（在棋盘上画出来的、单击格子、✎ 编辑）
尺寸都已经定了，不给模版，要改就拖右下角手柄。

抽屉里**没有**「位置与尺寸」那一栏：摆到哪一行哪一列、多大，都靠拖 ——
缩小一档看全局、100% 时对准格子，比填数字顺手。

规矩很简单：**格子之间不能重叠，也不能超出棋盘**。拖到不允许的位置会显示红色边框，松手不生效并给出提示。
复制格子会自动放到最近的空位；改小列数时放不下的格子也会自动挪到空位（会有提示）。

第一次在棋盘上动手时，现在的自动排布会**按你屏幕上的样子**（当前列数）固定成坐标——之后布局就固定了，
保存前可以先「导出」一份 JSON 备份。棋盘模式下工具条「列数」里的「自动」没有意义，会变灰。

改完随手 **⌘S / Ctrl+S** 就能保存（浏览器原本的「保存网页」被接管了），保存完会浮出「已保存」的提示。
只认不带 shift 的那个 —— ⇧⌘S 还是浏览器的「另存为」。

窄窗口下棋盘**不会重排，而是整体缩小**；缩到每格 96px 以下就改为横向滚动（保持构图，不把格子挤碎）。
12 列的布局在手机上要横向滚，想要手机友好就用 6 列以内。

**触屏上的拖拽**：按住格子约 **1 秒**才进入拖拽模式（会有一圈高亮和一下短震动），这之后再拖动就是移动位置；
短按仍然是打开编辑。按住期间指头滑动超过一点点（12px）就当你在滑动页面，不会误触成拖动。
右下角改尺寸的小方块不受这个限制——它是明确的抓取点，按下去就能拖。
手机上**新建格子**走棋盘上方的「＋ 添加格子」：落在最下面，再在抽屉里点尺寸模版。

**行数不设限**：棋盘只画到最底下那行格子再往下两行，拖到哪儿就长到哪儿，删掉底部的格子还会缩回去。
多出来的那两行只是空白画布，不会存进 `site.json`。要往下画格子，就从最后一行往下拖——
画布会跟着长。

### 窄屏重排（响应式）

棋盘是固定坐标，窄屏下默认只能整体缩小；缩到每格 96px 以下就变成横向滚动——手机上看就是
「一张要左右拖的小图」。管理页的 **响应式（窄屏重排）** 面板可以换掉这个行为：勾上以后，
电脑端保持棋盘原样，窄屏把格子**按顺序紧密重排**成 N 列，格子还是原来那么大、宽格子自动收到
N 列以内。

| 档位 | 默认阈值 | 默认行为 |
| --- | --- | --- |
| 桌面 | ≥ 1024px | 棋盘原样（你摆的构图） |
| pad | 640–1023px | 重排成 4 列 |
| 手机 | < 640px | 重排成 2 列 |

- 重排**不写进数据**：`site.json` 里的坐标一个字节都不会动，换设备、刷新都按你摆的那份渲染。
- 某一档选「不重排」= 那一档回到整体缩小 + 横向滚动。
- **默认关闭**，老站点维持原样；每个子管理员的小站各自设置。
- 阈值只是一条边界线，不改变棋盘本身的宽度要求：**12 列的棋盘要 ~1380px 才放得下**，
  所以 pad 阈值填 1024 时，1024–1379px 之间仍然是棋盘原样、仍然会横滚。想让它全程不横滚，
  把 pad 阈值填 1400 就行。

> 尺寸按「列 × 行」理解：`1x2` 是 2 列宽、1 行高的横向矩形。管理页里每个选项都带缩略图形，一眼能对上。

**类型**分三种，说的是**封面**长什么样：

- **图片封面**：格子上展示图片（支持上传，或直接填图片 URL），可选一个常显的角标文字。
- **网页封面**：封面本身就是一个 HTML 页面，直接铺在格子上——做**动态封面**就用它。
- **纯色封面**：只填一个底色，用来留白、分隔、补位。

三种类型**都可以再嵌一个 HTML 页面**（和封面是两回事）：填了之后，鼠标移上去右下角会浮出
放大角标，点格子或角标就把那个页面**全屏展开**——详见下面「嵌入的 HTML」。

三种格子都可以配**悬浮详情**，也都可以配**常显的角标文字**。鼠标移上去时详情面板从指定方向滑入：

- `滑入方向`：从左 / 从右 / 从上 / 从下。
- `覆盖比例`：`1/1` 覆盖整个格子，`1/2` 只覆盖一半（从哪边滑入就贴在哪一边）。
- `背景色` / `文字颜色` 自由配，背景色支持 8 位十六进制（末两位是透明度，例如 `#0b0a12f2`）。

**手机 / 平板上**没有「悬浮」，所以点击分两步：**第一下先把详情弹出来**（相当于桌面上的悬浮），
**第二下才真的「进去」**——跳链接或全屏展开嵌入的页面；如果这颗格子没有链接也没有嵌入页面，
第二下就是把详情收起来。点别的格子（或点卡片之间的空隙）会收起当前这颗。只有链接/嵌入、
没有详情面板的格子，仍然是「一点就进去」。

角标文字在手机上**照常显示**；有嵌入页面的格子，右下角的放大角标在触屏上常显、并且做得更大一些，
手指点得着——点它可以直接全屏展开，不用先看详情。

格子上还能配一个点击跳转链接。链接除了 `http(s)` 网址和站内文件地址，还可以填 `/admin`、`/editor`、`/user` 这三个页面——其中 `/admin` 和 `/editor` 会**自动带上当前 userid**，所以同一份内容里放一个 `/admin` 格子，站主点进 `/admin`、子管理员点进自己的 `/admin?userid=…`。

默认内容（`data/site.json`，也就是每个新注册用户的起点）的第一个 1×1 格子就是这样一个管理入口。

**链接和「嵌入的 HTML」互斥**——两者都绑在格子的点击上，同一时刻只有一个生效。抽屉里它们是并排的
两个按钮，点哪个下面就显示哪个的填写栏。

- **两边填的内容都保留**：切换只是换「哪个生效」，地址不会丢，随时点回来。生效的那个记在
  `clickMode` 里（`link` / `embed`）。
- 老数据没有这个字段时按老规矩推断：只填了链接就是链接，其余情况算嵌入。

管理页支持导出 / 导入整份 JSON 配置，方便备份和迁移。

## HTML：封面 与 嵌入

抽屉里是**两个**互不相干的页面字段，可以填不同的东西：

| | 用在哪 | 平时 | 点开 |
| --- | --- | --- | --- |
| **封面的 HTML** | 只有「网页封面」这个类型 | 直接铺在格子上渲染（**动态封面**就用它） | 不展开，它就是封面 |
| **嵌入的 HTML** | 三种类型都能填 | 不加载，格子上只有封面 | 全屏展开 |

- **上传文件**：管理页里选一个 `.html` 上传，文件存进数据目录的 `pages/`，跟着数据一起走，重新部署不会丢。
  同名文件直接覆盖，所以更新页面就是重新上传一次。
- **填地址**：也可以填外链（`https://…`），或者自己把文件放进数据目录的 `pages/` 再填 `/pages/xxx.html`。
- 页面可以带自己的 CSS / JS / 图片：放在同一层目录里、用相对路径引用即可（`pages/` 里的文件都能直接访问），
  也能引用 `/uploads/` 下的图片。

页面跑在 `iframe` 的 sandbox 里，**允许 JavaScript，但不给同源权限**：
页面里的脚本读不到本站的 cookie、调不了本站接口，也碰不到外面的主页。
代价是页面自己不能用 `fetch` 取本站的数据（`<script>`、`<img>`、`<link>` 这类标签照常用）。
封面和全屏用的是同一套沙箱（只有 `createFrame()` 一处实现）。

### 嵌入的 HTML：放大角标 + 全屏展开

填了「嵌入的 HTML」的格子，鼠标移上去时右下角会浮出一个**放大角标**（移上去还会再放大一点），
点格子或角标就把这个页面**全屏展开**——从格子所在的位置放大出来，关掉时缩回原处。

- **页面平时不加载**：只有点开那一刻才创建 iframe。省流量，也免得几个页面在后台一起跑；
  关掉之后页面里的脚本和定时器随 iframe 一起消失。
- 右上角有悬浮的关闭按钮，按 **Esc** 也行；角标能 Tab 到，回车/空格一样能展开。
- 同时有「悬浮详情」时，触屏上是**第一下看详情、第二下才展开**（点放大角标可以直接展开）；
  只有嵌入页面、没有详情时才是一点就开。
- 触屏没有 hover，放大角标常显且更大（34px），否则手指点不到。

> 「悬浮详情」的面板会盖住整个格子。封面本身是图片/纯色时无所谓；封面是**网页封面**（页面直接铺在
> 格子上、还要交互）时，建议把这个格子的悬浮详情关掉，否则鼠标一移上去详情面板就把页面挡住了。

## 文件

管理页里有个「文件」面板，可以浏览和管理数据目录里的三块内容，改完立即生效：

| 分类 | 目录 | 页面上的地址 | 放什么 |
| --- | --- | --- | --- |
| 站点资源 | `assets/` | `/assets/…` | 站点自己的图片：`logo.svg`、`title.png` |
| 上传的图片 | `uploads/` | `/uploads/…` | 格子里展示的图片 |
| 嵌入页面 | `pages/` | `/pages/…` | HTML 页面及它自带的 css / js / 图片 |

每个文件都能复制链接、在新标签页打开、删除；上传同名文件就是覆盖。
正在被格子引用的文件会标出「N 个格子在用」，删除前也会提醒。

`assets/` 里那两个文件是首次启动时从仓库的 `assets/` 播种过去的，之后以数据目录里的那份为准：
想换站点图标或标题图，直接在这里传一个同名的上去就行，不用改代码、也不用重新部署
（要用别的文件名也可以，把主页引用它的地方一起改掉即可）。

## 创作工具（`/editor`）

左边一条工具栏、右边工作面板。两个小工具，做出来的图可以直接存进数据目录（存文件要登录管理密码，
和管理页同一个）。管理页右上角有入口。

### TXT → PNG

纯色背景 + 纯色文字，尺寸按橱窗格子来（`1x1` / `1x2` / `1x4` / `2x2` / `2x4`，基准格子像素 128–512 可选）。

- **字体用本机装的那些**，所以同一份配置换台电脑渲染出来会不一样。下拉按无衬线 / 衬线 / 等宽 / 圆体分组，
  给了常见的中英文字体栈。
- 字号可手填，也可以勾「自动适应画布」让它撑满；支持多行（回车换行）、粗体斜体、左中右对齐、行距。
- 背景可以设成透明，用来做叠在格子上的字。
- 导出：**下载 PNG**，或**存到服务器**（选 `uploads/` 或 `assets/`，同名覆盖）。

预览用的就是导出分辨率的那块画布，所见即所得。

### PNG → SVG

- **矢量描摹**：把同色区域变成真正的 `<path>`。做法是找「这个颜色 / 不是这个颜色」之间的像素边，
  首尾相接绕成闭合轮廓，再按「轮廓简化」的容差抽稀；洞（比如「口」字中间那块）是独立轮廓，
  靠 `fill-rule="evenodd"` 挖空。适合扁平色块——本页 TXT→PNG 的产物、logo、图标；照片会变成海报风。
- **直接嵌入**：原像素 base64 进 `<image>`，形状一点都不动，只是换个壳。

原图颜色数超过「颜色数」上限时会用 k-means 自动归并（抗锯齿的边缘会碎成几百种颜色，不归并的话
路径又碎又大），界面会注明「原图 N 色，已归并」。转换完可以和原图并排对比，并显示轮廓数、
节点数和文件大小。

两个工具的产物都落在 `uploads/` 或 `assets/`，就是「文件」面板里那两块；把 `/uploads/…` 填进格子的
图片地址就能用。

## 多用户（子管理员）

`/user` 是注册 / 登录页：注册要填**用户名 + 密码 + 邀请码**。注册成功自动登录，然后进入
`/?userid=<userid>` —— 一份用默认示例内容铺好的、属于他自己的橱窗。他的管理页是
`/admin?userid=<userid>`，创作工具是 `/editor?userid=<userid>`。

**数据完全隔离**：每个用户在 `/app/users/<userid>/` 下有一份自己的小站

```
/app/users/<userid>/site.json      # 他自己的格子配置
/app/users/<userid>/assets/        # 他自己的 logo.svg / title.png（首启从仓库播种，可替换）
/app/users/<userid>/uploads/       # 他自己上传的图片
/app/users/<userid>/pages/         # 他自己嵌入的 HTML 页面
```

页面上引用这些文件的地址是 `/u/<userid>/assets|uploads|pages/<文件名>`（站主的还是 `/assets/…`
那套裸路径，两者互不影响）。权限上，用户只能改自己的站点和文件；站主能改所有人的。

**userid** 是 64 位十六进制，三段拼起来：

| 段 | 长度 | 内容 |
| --- | --- | --- |
| 1 | 16 | 用户名的 SHA-256 前缀 |
| 2 | 32 | 注册时间戳（十六进制，左补零） |
| 3 | 16 | 随机 |

**邀请码**由站主生成，128 位随机（32 位十六进制），带使用次数上限（默认 10 次，见管理页）。
注册时才扣次数，注册失败不扣。

### 站主视角：用户与邀请码

管理页（自己的 `/admin`，不带 userid）里多了一个「用户与邀请码」面板：

- **邀请码**：填可用次数和备注 → 生成；列表里显示「已用 / 上限」和剩余次数，可以复制、删除。
  用完的码会标「已用完」，删掉不影响已注册的人。
- **用户**：列表显示用户名、注册时间、userid 前几位。每行三个按钮：
  `↗` 看他/她的主页、`✎` 代管（进他的 `/admin?userid=…`，用站主身份就能编辑）、
  `✕` 删除（内容归档到 `/app/users/.deleted/<userid>-<时间>/`，账号变成墓碑）。
- **已删除**：面板底下单列一块，显示删掉的账号和「内容还在归档里 / 归档已清理」。点 `↺` 恢复——
  **账号、原密码和内容一起回来**；归档被清过的话，账号照样回来，内容从默认内容重新开始；
  这个名字被别人占了会提示先处理重名。
- 也可以**直接添加用户**（用户名 + 初始密码），不需要邀请码。

用户的密码用 `scrypt` 加随机盐存在 `/app/data/users.json`（邀请码在 `/app/data/invites.json`）；
会话 cookie 里带的是「谁」——站主本人，或某个 userid。

## 站点信息

管理页顶部的「站点信息」面板里可以改站点标题、主题强调色、标题栏文字，以及页脚的三块文字；
**每行列数**和**格子间隔**在棋盘上方的工具条里（见上）。

标题栏是主页 Logo 下方的那句话，**默认不显示**；勾选「在主页显示标题栏」并保存后才会出现在主页上。

### 页脚

页脚分左 / 中 / 右三块，都在管理页里改：

- **左侧**：Logo 后面的站点署名。
- **中间**：ICP 备案号，永远居中、优先显示；两侧文字太长时会各自横向滑动，不会把中间挤走。
- **右侧**：补充文字（版权之类），留空就不显示。

主页上的备案号是可点的超链接，默认指向工信部备案系统 `https://beian.miit.gov.cn/#/Integrated/index`（新标签页打开）。
管理页里的「备案号链接」填了就按填的走，只接受 `http(s)://` 开头的绝对地址，填别的会被清空、退回默认。

备案号也可以在部署时用环境变量塞进去，不用登录管理页：

```bash
ICP_NUMBER='京ICP备00000000号' ./build_run.sh
```

环境变量只在管理页里没填过备案号时生效；管理页里填过就以管理页的为准，把管理页里那个框清空又会退回环境变量。

## 本地开发

不需要安装任何依赖（Node 要 **22.5 以上**——账号库用的是 Node 自带的 `node:sqlite`）：

```bash
ADMIN_PASSWORD=dev node server/index.js
# http://127.0.0.1:3000/       主页
# http://127.0.0.1:3000/admin  管理页
```

运行时数据写在 `data.local/`（不在 git 里）：首次启动时从 `data/site.json` 拷一份示例内容，
并把仓库 `assets/` 里的图片播种到 `data.local/assets/`（同样是被服务的那一份）。
仓库里的 `data/site.json` 只是示例内容、**只读取种子**，在管理页里怎么改都不会动到它。
想换个地方放运行数据就设 `DATA_DIR`；想让本地预览回到初始状态，删掉 `data.local/` 重启即可。

> 这里说的是 `node` 直跑。用 `build_run.sh` 跑容器时数据放在宿主机的 `/app/data`，
> 见下面「数据」一节——两者互不影响。

想改棋盘的实现（尺寸、格线、拖拽吸附这些几何部分）之前，先看 [Agent.md](Agent.md)——
那份文档写的是实现契约和踩过的坑，不是用法。

## 部署

只需要 Node 后端的话，一条命令构建并启动：

```bash
./build_run.sh
```

脚本会：构建镜像 → 停掉旧容器 → 启动新容器 → 等应用就绪 → 核对数据没被动过 → 打印状态和日志。

```bash
./build_run.sh --update     # 更新代码用这条：git pull → 构建 → 重启，数据原样保留
./build_run.sh --no-build   # 不重新构建，只重启
./build_run.sh --rebuild    # 不用缓存重新构建
./build_run.sh --stop       # 停止并删除容器
./build_run.sh --logs       # 跟踪日志
```

`--update` 就是更新代码用的那条：拉 git 里的新代码重建镜像，数据原样保留——数据目录
（`HOST_DATA_DIR`，默认 `/app/data`）从头到尾只是一个挂载点，没有任何东西往里写，
部署完还会核对一遍 `site.json` 的指纹。

### 更新已经部署的站点

代码是 `git pull` 下来的、内容是挂载进去的，所以更新代码就三步：

```bash
# 1. 本地：提交并推上去
git add -A && git commit -m "..." && git push origin main

# 2. 服务器：拉代码 → 重建镜像 → 重启 → 核对数据
ssh <你的服务器>
cd /root/gilloffline
set -a && . ./.deploy.env && set +a     # 部署用的环境变量（ADMIN_PASSWORD 等）放这个文件里，不进 git
./build_run.sh --update
```

`--update` 内部就是一次 `git pull --ff-only` 加一次完整部署，不用自己先拉。
跑完应该是这样：

```
✔ 镜像构建完成
✔ 容器已启动
✔ 应用已就绪
✔ 数据校验：site.json 与部署前完全一致
```

最后那行要是**黄色警告**（`和部署前不一样了`），说明 `site.json` 在部署期间被改过——
正常部署不该出现，去 `HOST_DATA_DIR` 看一眼。之后浏览器刷新一下页面就行
（静态文件是 `no-cache` + ETag，普通刷新就能拿到新版）。

两条纪律：

- **别在服务器的仓库里直接改文件**：`git pull --ff-only` 撞上本地改动会直接失败（脚本会明确报错退出，不会硬来）。
- 改了**内容**（格子、图片、嵌入页面）不用走这套，管理页里改完立刻生效。

### 构建卡在 Docker Hub

国内服务器上 `docker build` 可能第一步就失败：

```
failed to resolve reference "docker.io/library/node:22-alpine": ... i/o timeout
```

**站点不受影响**——脚本在构建这步就退出了，旧容器照常服务。原因一般是本地没有基础镜像、
又连不上 Docker Hub。拉一份国内能通的、再打上标准标签，之后构建就只用本地镜像了：

```bash
docker pull docker.1panel.live/library/node:22-alpine
docker tag docker.1panel.live/library/node:22-alpine node:22-alpine
./build_run.sh --update
```

要是想一劳永逸，给 docker 配个镜像加速（`systemctl restart docker` 会让容器中断十几秒，
`--restart unless-stopped` 会自动把它拉回来，`docker ps` 确认一下即可）：

```bash
cat > /etc/docker/daemon.json <<'EOF'
{ "registry-mirrors": ["https://docker.1panel.live"] }
EOF
systemctl restart docker && docker ps
```

> 镜像加速源都不是官方服务，介意的话换成你信得过的地址。`docker pull` + `docker tag`
> 这个办法换成任何能连通的镜像源都适用，不一定非要用上面那个。

### 日常运维

```bash
./build_run.sh --no-build     # 不重建，只重启（改了 .deploy.env 里的变量时用）
./build_run.sh --rebuild      # 不吃缓存重新构建（怀疑构建结果不对时用）
./build_run.sh --logs         # 跟踪日志，Ctrl+C 退出
./build_run.sh --stop         # 停掉并删除容器
docker restart gilloffline    # 比如换了证书，直接重启容器即可
```

容器挂了会自动重启（`--restart unless-stopped`），健康检查每 30 秒打一次 `/api/health`。

### 证书

把你的证书放进宿主机的 `/app/ssl` 目录，容器挂载到同一个路径（只读）：

```
/app/ssl/gilloffline.online.pem     # 证书链（含中间证书）
/app/ssl/gilloffline.online.key     # 私钥
```

文件名不一样就改环境变量：

```bash
SSL_CERT_FILE=example.com.crt SSL_KEY_FILE=example.com.key ./build_run.sh
```

证书就绪时 nginx 监听 443 并启用 HSTS，80 端口自动 301 跳转到 HTTPS。
**如果没找到证书，容器照样会启动**，只是只监听 80 端口并打印提示——不会因为证书没放好就起不来。
放好证书后重新跑一次 `./build_run.sh` 即可。

> macOS 的根分区是只读的，无法创建 `/app`。在 Mac 上测试请指定别的目录：
> `HOST_SSL_DIR=$HOME/certs ./build_run.sh`（容器里还是挂在 `/app/ssl`）。

#### 用 Let's Encrypt 自动续期

容器里的 nginx 把 `/.well-known/acme-challenge/` 指向 `/var/www/acme`，宿主机目录对应 `HOST_ACME_DIR`（默认 `/var/www/acme`），
所以在宿主机上装个 certbot 就能走 webroot 验证——申请和续期都不用停容器：

```bash
apt install -y certbot
certbot certonly --webroot -w /var/www/acme -d example.com -d www.example.com

# 把签好的证书复制到 /app/ssl，文件名和 SSL_CERT_FILE / SSL_KEY_FILE 对上
cp -L /etc/letsencrypt/live/example.com/fullchain.pem /app/ssl/example.com.pem
cp -L /etc/letsencrypt/live/example.com/privkey.pem   /app/ssl/example.com.key
docker restart gilloffline
```

把最后三条命令存成一个脚本放进 `/etc/letsencrypt/renewal-hooks/deploy/`，
certbot 自带的 `certbot.timer` 每次续期成功后都会自动调用它，容器随即换上新的证书，之后就不用管了。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 无（必填） | 管理页密码。不设置时管理功能整体禁用，不会退化成默认密码 |
| `ICP_NUMBER` | 无 | 页脚中间的 ICP 备案号；管理页里没填过时生效 |

| `HOST_DATA_DIR` | `/app/data` | 宿主机数据目录（站主自己的站），容器内挂在同一个路径 |
| `HOST_USERS_DIR` | `/app/users` | 宿主机用户目录（每个子管理员一个子目录），容器内挂在同一个路径 |
| `SERVER_NAME` | `_` | nginx `server_name`，填你的域名 |
| `SSL_CERT_FILE` / `SSL_KEY_FILE` | `gilloffline.online.pem` / `gilloffline.online.key` | 证书文件名 |

```bash
ADMIN_PASSWORD='你的密码' SERVER_NAME=example.com HOST_SSL_DIR=/etc/letsencrypt/live/example.com ./build_run.sh
```

### 数据

代码在 git 里，内容全在数据目录里，两边彻底分开。数据目录默认是宿主机的 `/app/data`
（和证书目录 `/app/ssl` 一个位置、一个风格），容器里挂在同一个路径：

```
/app/data/site.json        # 站主自己的全部格子配置
/app/data/.session-secret  # 会话签名密钥（自动生成）
/app/data/assets/          # 站主自己的图片（logo.svg / title.png），首启从仓库播种
/app/data/uploads/         # 站主上传的图片
/app/data/pages/           # 站主上传的 HTML 页面（及其 css / js / 图片）
/app/data/gilloffline.db   # 账号 + 邀请码（SQLite，见下）

/app/users/<userid>/       # 每个子管理员的小站：site.json + assets/ + uploads/ + pages/
/app/users/.deleted/       # 删除用户时归档的目录
```

站主的站全在 `/app/data`，用户的小站在 `/app/users`，两个目录各备一份就是整个站：

```bash
cp -a /app/data /root/data-backup-$(date +%F)
cp -a /app/users /root/users-backup-$(date +%F)
```

升级、重建镜像、`--update` 拉代码都不会动这个目录——它只是挂载进容器，没有任何东西往里写。

`--update` 跑完会打印一行「数据校验：site.json 与部署前完全一致」——那就是部署没有动过内容的意思；
如果这行变成警告，说明数据在部署期间被改过，去 `/app/data` 看看。

仓库里的 `data/site.json` 和 `assets/` 都不属于运行时数据：它们只是提交进 git 的初始内容，
只在数据目录里还没有的时候被播种一次（`assets/` 只在那个目录不存在时才抄，之后删掉某个文件不会被重新塞回来）。

### 账号数据库

用户账号和邀请码存在 `/app/data/gilloffline.db` 里，用 Node 自带的 `node:sqlite` ——
**不用装任何依赖**，也不用另外跑数据库服务。两张表：

| 表 | 存什么 |
| --- | --- |
| `users` | userid、用户名（大小写不敏感的唯一索引，且**只约束未删除的行**）、注册时间、scrypt 盐和哈希；删除后留一条墓碑（`deleted_at` + 归档路径） |
| `invites` | 邀请码、可用次数、已用次数、备注 |

站点的格子有两种排布方式，由 `site.layout` 决定：`flow`（默认，有序列表 + CSS 自动排）和 `board`（每个格子带
`pos: {x, y, w, h}` 坐标，单位是格）。`pos` 是唯一的尺寸来源，旧文档里的 `size` 关键字仍然有效（作为 `flow`
的尺寸和兼容输入）。服务端保存时会做一次碰撞检查：坐标越界或和别的格子重叠的，会被挪到第一个空位并打日志——
CSS grid 对显式定位的元素不做任何防重叠，最后这道防线在服务端。

网站的**内容**仍然是一个个文件（`site.json`、`assets/`、`uploads/`、`pages/`），只有账号和邀请码进库 —— 编辑器和文件面板直接操作文件，不用跟着改。
从更早的版本升级上来时，首次启动会自动把 `users.json` / `invites.json` 导进库，再把这两个文件改名成 `*.imported` 留档（确认无误后可以自己删）。

数据库开的是 WAL 模式，所以目录里会多出 `gilloffline.db-wal` / `-shm`，备份时一起备。

从旧版本升级上来时，`build_run.sh` 会把旧数据搬到 `/app/data`（旧目录原样留着不删，确认没问题后可以自己清理）：

- 上一版的数据在 `data.local/` → 整个目录搬过来（含 `.session-secret`，登录状态也不会掉）；
- 更早的版本把上传的图片放在仓库的 `data/uploads/` → 图片复制过来，`site.json` 还是走示例播种。

## 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/site` | 公开 | 读取整站内容（带 `?userid=` 就是那个用户的小站） |
| `GET` | `/api/session` | 公开 | 当前是否已登录、是否配置了密码 |
| `GET` | `/api/health` | 公开 | 健康检查 |
| `POST` | `/api/login` | 公开 | 站主传 `{password}`，用户传 `{username, password}`，下发会话 cookie |
| `POST` | `/api/register` | 公开 | `{username, password, invite}` 注册并登录 |
| `GET` `POST` `DELETE` | `/api/users` | 站主 | 列出（含已删除）/ 直接添加 / 删除用户 |
| `POST` | `/api/users/restore` | 站主 | 恢复一个已删除的用户（`{ userid }`）|
| `GET` `POST` `DELETE` | `/api/invites` | 站主 | 列出 / 生成 / 删除邀请码 |
| `POST` | `/api/logout` | 公开 | 清除 cookie |
| `PUT` | `/api/site` | 需登录 | 覆盖保存整份配置（自己的站，或站主代管） |
| `GET` `POST` `DELETE` | `/api/files?kind=…` | 需登录 | 列出 / 上传 / 删除文件，`kind` 是 `assets` / `uploads` / `pages` |

## 安全

- 密码只在环境变量里，不落盘；比对用定长哈希 + `timingSafeEqual`。
- 会话是 HMAC 签名的 HttpOnly cookie（`SameSite=Strict`，HTTPS 下自动加 `Secure`），密钥存在数据卷里，重启不掉线。
- 登录失败按 IP 限流：5 分钟内 8 次失败即拒绝。
- 保存的每个字段都在服务端重新校验：颜色只接受十六进制字面量，链接只接受 `http(s)` 和站内路径，避免存进 CSS 或 HTML 里造成注入。
- 前端全部用 `textContent` 渲染，不走 `innerHTML`。
- 上传限 8 MB，每类文件只接受对应的类型（图片；页面那类还接受 HTML / CSS / JS / JSON），
  扩展名跟着声明的 Content-Type 走，文件名做白名单清洗；`/assets/`、`/uploads/`、`/pages/`
  的静态文件读取都做了路径逃逸检查。
- 每个用户的内容都在自己的目录里，接口一律按会话里的身份判定归属：别人（包括猜出 userid 的人）
  只能读、不能改；站主例外。用户密码用 `scrypt` + 每用户随机盐，不是明文也不是单轮哈希。
- 主页嵌入的 HTML 页面跑在 `iframe sandbox` 里，不给 `allow-same-origin`：页面脚本拿不到本站 cookie、
  调不了本站接口，也读不到外层页面的 DOM（实测 `document.cookie` / `parent.document` / `localStorage` 全部抛 SecurityError）。
  嵌别人的页面进来也不会威胁到管理页。
- nginx 侧限制请求体 12 MB，并附带 HSTS / `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`。
- 后台进程以非 root 的 `node` 用户运行（只有 nginx master 需要 root 来监听 443）。
